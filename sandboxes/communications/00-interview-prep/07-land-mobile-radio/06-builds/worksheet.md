## 1. Why this matters (Etherstack context)

Etherstack's **core business is LMR protocol stacks**. A stack is built from small, brutally precise components: a **codec** (the FEC that protects control words), a **frame
parser/splitter** (find sync, cut the stream into fields, dispatch), and a **call-control state machine** (who may talk). In interviews you are asked to **build**
these, usually on a whiteboard or in a shared editor, with the interviewer probing *why* each design decision. These four builds are the capstone of the module: each is small enough to finish in an hour and
each tests a different skill — algebra (Golay), robust parsing (P25 parser), bit-level layout (DMR), and state-machine design (floor control).

## 3. Concept build-up

### 3.1 How to approach a build (the interview method)

1. **Restate the contract** with concrete numbers (a 12-bit word in, 23 bits out; a 288-bit slot).
2. **Write the test first** — a hand-computed example (§4) before any loop.
3. **Smallest correct version**, then the invariant (e.g., "decode(encode(x) ^ e) == x for weight(e) ≤ 3").
4. **Exhaustive or property testing** where the space is small (4096 Golay codewords; all ≤4-bit error patterns).
5. **Sanitizers on** (`-fsanitize=address,undefined`): bit-twiddling code is UB-prone (shift widths, signed overflow).
6. **Deterministic synthetic data** (fixed seed) so failures reproduce.

### 3.2 Build A — Golay(23,12,7) and Golay(24,12,8)

*Concrete first.* 12 data bits go in; 11 parity bits are appended; 23 bits come out. Up to **3** flipped bits are fixable.
**Encoding = polynomial division over GF(2).** Treat bits as polynomial coefficients; `g(x) = x¹¹+x¹⁰+x⁶+x⁵+x⁴+x²+1 = 0xC75`. Systematic encode: shift info left by 11 (`info·x¹¹`),
divide by *g*, append the remainder: the result is divisible by *g* ⇒ a codeword. *Why division?* Cyclic codes are exactly the multiples of *g*; the remainder
is the unique fix-up that makes the word a multiple (pack 01 §3.3).

**Decoding via syndromes.** The *syndrome* of a received word is its remainder mod *g*. Codewords have syndrome 0, and the syndrome of `codeword + error` equals the syndrome of the **error alone**. So a table
`syndrome → error pattern` is all a decoder needs.

**Why it's perfect.** The number of error patterns of weight ≤ 3 in 23 positions is `1 + 23 + 253 + 1771 = 2048 = 2¹¹` — exactly the number of possible syndromes. Two distinct patterns of weight ≤ 3 cannot share a syndrome,
because their sum would be a nonzero codeword of weight ≤ 6, but the minimum weight is 7. So the **2048 patterns fill the 2048 syndromes exactly once**: every received word is within distance 3 of one codeword. (Sphere-packing: 4096 · 2048 = 2²³.)

**Cost of perfection.** There is **no** "I can't decode this". With ≥4 errors the decoder silently picks a *different* codeword. To *detect* 4 errors add an **overall parity bit** (Golay(24,12,8)):
decode the 23 bits, then check the parity bit against the corrected word: `total = e + m` (e = flips decoded in the 23-bit part ≤3, m = 1 if the parity bit disagrees). Accept if total ≤ 3; otherwise declare **uncorrectable**. Q3 proves every 4-error pattern is caught.

> **Misconception box — "perfect means it corrects everything."** Perfect means *no wasted syndromes*, not *no failures*. Beyond 3 errors a perfect code miscorrects with certainty.

> **Misconception box — "the extra parity bit adds correction power."** It adds **detection** (distance 7 → 8): still corrects 3, now also *detects* 4.

### 3.3 Build B — a P25-style synthetic frame parser

Frames are streams of **symbols** (dibits). The pipeline (each step has a reason):

1. **Find sync on raw symbols** (tolerant). *Why before anything else?* You can't know where status symbols fall until you know where the frame starts: status symbols are counted from the frame start.
   *Why does raw search work?* The first status symbol arrives after **35** symbols, but the sync is only 24, so the sync is never interrupted. Tolerance: accept ≤ *e* bit errors out of 48; false-sync probability on random data ≈ Σ C(48,k)/2⁴⁸ (pack 01; 7.6·10⁻¹⁰ at e = 4).
2. **Strip status symbols** relative to that start: the symbol at relative index *k* is a status symbol iff `(k+1) % 36 == 0` (after every 35 data symbols). Equivalent mapping: data symbol *k* sits at air index `k + k/35`.
   LDU check: 840 data symbols → 24 status → **864 air symbols = 1728 bits = 180 ms** ✔.
3. **Pack the 32 NID symbols into 64 bits** (first symbol = most significant dibit).
4. **Decode NID by candidate matching.** Valid NIDs are only `(NAC, DUID)` with 7 legal DUIDs and the NAC(s) the receiver is configured for. Encode each candidate (`nid_encode64`), pick the one closest in Hamming distance, require
   distance ≤ 11 **and uniqueness**. *Why no BCH decoder?* The extended code has minimum distance 24, so any word within 11 bits of a codeword is within 11 of **exactly one** — nearest-candidate equals bounded-distance decoding, with less code, and it uses prior knowledge (only 7 DUIDs, only our NACs) to cut false accepts (Q6).
5. **Dispatch on DUID:** HDU → header, LDU1/LDU2 → voice, TSBK → control, PDU → data, TDU/TDULC → terminator; fixed-size frames have a known payload (LDU: 784 symbols = 1568 bits — VERIFY).
6. **Robustness:** a **false sync** (sync-looking pattern + garbage NID) must not stop the search — move on (`pos + 1`). A **truncated** frame must return *nothing*, not zero-padding. Extra bytes after a fixed-size frame belong to the next thing.

> **Misconception box — "strip the status symbols first, then search for sync."** Chicken-and-egg: stripping needs the frame start, which needs the sync (Q5, Q7).

> **Misconception box — "an NID that decodes is a valid frame."** A random 64-bit word decodes with probability ≈ 3.5·10⁻⁷ at tolerance 11 (one NAC): rare, not zero. Check the NAC you expect and the DUID's plausibility.

### 3.4 Build C — a DMR burst splitter

Concrete layout (this pack's stream model — VERIFY against TS 102 361-1): **slot = 24-bit gap/CACH + 264-bit burst = 288 bits = 30 ms at 9600 bit/s**; burst = **108 | 48 | 108**. A voice burst carries **3 × 72-bit** AMBE+2 frames = 216 bits = 2 × 108:
frame 0 = first 72 bits of the first half; **frame 1 straddles the middle** (last 36 bits of the first half + first 36 of the second); frame 2 = last 72 of the second half. The 48-bit middle holds **sync** (burst A of each voice superframe) or **embedded signalling** (B–F).

**Finding the slot phase.** A stream arrives with an unknown offset. Idea: *the sync word sits at a fixed place* (bits 132–179 of each slot). For each of the 288 possible phases, cut the stream into slots and **count sync hits** in the middles; the true phase gets the hits; wrong phases see random bits.
Why it's reliable: the chance that 48 random bits land within 4 bit errors of any of 4 sync words is ≈ 3·10⁻⁹ (Q10).

> **Misconception box — "the middle is part of the voice."** 3 × 72 = 216 = 2 × 108: the 48 middle bits are *never* voice; they carry sync/signalling.

### 3.5 Build D — the floor-control state machine

A talkgroup call on one channel is a **state machine** with three states: **Idle** (no channel), **Active** (one talker), **Hang** (channel held, nobody talking). Events: `press(unit, emergency)`, `release(unit)`, `tick(ms)`.
*Derive the table, don't improvise:* for each state × event decide the next state and the **action** reported to the caller (the system around the FSM turns actions into messages). Time is an **input** (`tick`), never read from a clock:
tests are deterministic and the FSM runs identically on a bench and on a DSP.

| State \ Event | press(u) | release(u) | tick(ms) |
|---|---|---|---|
| Idle | → Active (Granted) | none | none |
| Active, u = talker | none (duplicate) | → Hang (Released) if talker, else none | talk timer; at limit → Hang (TalkTimeout) |
| Active, u ≠ talker | emergency over normal → Preempted; else Denied | none | same |
| Hang | → Active (Granted, no new channel grant) | none | hang timer; at limit → Idle (HangExpired) |

Design choices to defend: **talker 0 means "nobody"**; unit IDs are nonzero; emergency is a *per-call* property that ends with the call; one transition per tick (the caller ticks in small steps); every grant/preempt resets the talk timer
(otherwise a preempting emergency caller inherits the old talker's elapsed time). Known hole (Q12): a stuck PTT that times out can immediately re-acquire the floor from Hang.

> **Misconception box — "a state machine is a switch on the state."** The *table* is the design; the switch is the encoding. Write the table first, then test every cell.

## 4. Fully worked example

**(a) Golay by hand.** `g = 0xC75` (weight 7). Info `1` → `1·x¹¹` = `0x800`; bit 11 is set, XOR `g`: `0x800 ^ 0xC75 = 0x475` = remainder, so the codeword is `0x800 | 0x475 = 0xC75` = *g itself* ✔.
Powers of *x* mod *g* (each step shift left, reduce if bit 11 set): x¹¹ = `0x475`, x¹² = `0x49F`, x¹³ = `0x54B`, x¹⁴ = `0x6E3`, x¹⁵ = `0x1B3`. So a single error at codeword bit 15 has **syndrome `0x1B3`**; errors at bits 15 and 0 have syndrome `0x1B3 ^ 0x001 = 0x1B2`; the table maps `0x1B2 → bits {15, 0}`.
Info `3`: `x·g = 0x18EA` has info part `0x18EA >> 11 = 3` ⇒ encode(3) = `0x18EA`; info `2` = encode(3) ⊕ encode(1) = `0x18EA ^ 0xC75 = 0x149F` (weight 8 ✔ ≥ 7).

**(b) Parser arithmetic.** Data symbol *k* → air index `k + k/35`: *k* = 34 → 34; *k* = 35 → 36 (air 35 is status); *k* = 70 → 72 (air 71 is status); *k* = 839 → 839 + 23 = 862, and air 863 is the 24th status symbol: 864 total.
Packing `{1,2,3,0}` → `01 10 11 00 = 0x6C`.

**(c) DMR phase arithmetic.** Stream has 100 junk bits, then slots. Slot *k* starts at `100 + 288k`; its middle starts at `+24 + 108 = +132`. A sync found at bit 1960 ⇒ phase = `(1960 − 132) mod 288 = 1828 mod 288 = 100` ✔ (1828 = 6·288 + 100).
Voice frame 1 bits (burst-relative): `72…107` and `156…191`; frame 2: `192…263`.

**(d) Floor-control trace** (hang 3000 ms, talk limit 60 000 ms):

| Step | Event | Result | State |
|---|---|---|---|
| 1 | `press(1)` | Granted, talker 1 | Active |
| 2 | `press(2)` | Denied | Active |
| 3 | `release(1)` | Released (previous 1) | Hang |
| 4 | `tick(1000)` | none | Hang |
| 5 | `press(2)` | Granted, talker 2 | Active |
| 6 | `press(3, emergency)` | Preempted (previous 2) | Active, emergency |
| 7 | `release(3)` | Released | Hang |
| 8 | `tick(3000)` | HangExpired | Idle |
